Blacknet · Oblivious Message Retrieval

BlackLemon
InstantOMR

Find what's yours in the dark. The node scans every message for you — and learns nothing: not your key, not which messages match, not what they say.

On a public ledger, every message is visible to everyone. OMR lets a recipient outsource the search for their own mail to an untrusted node, using post-quantum lattice encryption so the node computes on ciphertext it can never open.

What the node holds is the whole noisy ring. Only your secret key tells whether a coefficient fell into a lemon band. A message is yours only if every coefficient did.

01

Clue

Each message leaves a small public clue on-chain — the non-secret parts (ct.a, ct.b) of a BlackLemon ciphertext. Anyone can see it; it reveals nothing on its own.

on-chain · public
02

Detection key

You publish your key encrypted: Enc(s) and Enc(sk.b). The node holds it but can't read it — it's just ciphertext.

you → node
03

Oblivious detection

For every clue, the node computes Enc(d) = ct.a + ct.b·s + sk.b homomorphically — the exact BlackLemon decryption, run entirely on encrypted data.

node · sees ciphertext only
04

Bootstrap → pertinence bit

A programmable bootstrap maps each coefficient of d by its band (see the ring above) into one encrypted verdict: Enc(PV), the bit "this one is mine."

node · still blind
05

Compaction

The node multiplies each Enc(PV) by its payload and folds all N messages into just O(k̄) buckets — a digest whose size depends on how many are yours, not on how many exist.

node · O(k̄) out
06

Recover

You download the tiny digest and solve it locally with your key, recovering exactly your messages — having sent and received a constant trickle of data.

you · decrypt
◑

Across the entire scan the node never learns your key, which messages matched, or what any payload says. Every step runs on ciphertext; the bands only ever open under your secret.
